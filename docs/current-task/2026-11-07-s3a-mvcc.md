# S3A · MVCC 核心与事务契约

基线为 Raft 冻结提交 `39d0acf`。本轮在 `src/transaction/core/` 实现内存引擎，公共事务历史放在 `src/contracts/transaction.ts`。S3A 的验收停点是确定性隔离测试与写偏差。后续持久化、恢复及真实故障实验分别在 S3B、S3C、S3D 验收。

## 状态所有权与标识

- `TransactionEngine` 独占事务 ID 分配、活跃事务、私有写集、提交序列和锁。事务结束后返回按操作顺序排列的历史，供调用方采集。
- `VersionStore` 维护每个键按提交序列递增的版本链。每次 PUT 或 DELETE 分配 `txnId:事务内写序号` 作为稳定的更新及版本 ID。提交时每键最后一笔私有写进入版本链，其余写仍保留在历史中。
- `commitSeq` 从 0 开始。每个成功提交（含只读事务）占用一个新序号，同一次提交发布的全部版本共享该序号。中止不消耗提交序号。
- PUT 的 `null` 是有效值。DELETE 生成墓碑。读取墓碑返回 `found: false` 并保留读到的墓碑版本 ID。读不到任何版本时，观察版本 ID 为 `null`。

## 事务状态机

```text
BEGIN 成功 → active → COMMIT 成功 → committed
                  ├→ SI 同键写冲突 → aborted
                  └→ ABORT → aborted
BEGIN 锁冲突 → LOCK_CONFLICT
```

活跃事务的写只进入私有写集。SI 提交时先检查全部待写键。任一键在开始快照之后有已提交版本（含墓碑），整笔事务中止。通过检查后同步发布全部版本，并释放锁。显式中止同样释放锁并丢弃私有写。已结束的 ID 再次操作时报告 `TXN_NOT_ACTIVE`。

## 隔离级别与读取

```text
RC: BEGIN → READ 取当前 commitSeq → 私有写优先 → 版本链上最新可见版本
SI: BEGIN 固定 snapshotSeq → READ 沿用 snapshotSeq → 私有写优先 → 版本链上最新可见版本
AS OF(key, seq): 仅查询已提交链，取 commitSeq <= seq 的最后一个版本
```

RC 允许非重复读。同一键上的 RC 写按提交次序发布。SI 的读取视图固定，同键遵循先提交者胜出，跨键写偏差可以发生。AS OF 接受 `0..当前 commitSeq` 内的整数，0 表示初始空状态。 [隔离语义参考](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/02/tr-95-51.pdf)

调用方可在 BEGIN 时为业务约束申请具名排他锁，例如 `on-call`。锁归成功开始的事务所有，冲突立即返回，重试须重新 BEGIN。锁先于 SI 快照生效，参与同一约束的事务约定使用相同的锁名，普通读写继续按 MVCC 规则执行。

## WAL 与验证器的衔接

写记录含键、稳定更新 ID、值或墓碑。读记录含键、可见边界、读结果与实际版本 ID，来源区分已提交链、本事务私有写和缺失。历史包含事务隔离级别、SI 开始快照、终态和成功提交的序号。验证器可由终态及每键最后一条写识别发布版本，并区分私有读与跨事务读。

S3B 将更新 ID 带入 UPDATE，沿用 COMMIT 中的 `commitSeq` 作为版本可见顺序，另用 WAL 的 LSN 标识记录。持久化提交需在冲突校验通过后先刷盘 COMMIT，再发布版本与确认结果。AS OF LSN 可在持久化层按 COMMIT 记录定位对应提交序号。恢复需沿用原事务 ID 与版本 ID，并从持久记录恢复分配高水位，避免重用历史身份。
