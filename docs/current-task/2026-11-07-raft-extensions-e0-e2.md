## E1 · 批量提交

HTTP 队列按任期合并同时到达的单条请求，5 ms 或满 64 条即提交。Core 用一次 `replaceSuffix` 追加连续条目，为每条登记独立的等待者。切换任期时，尚未入日志的旧批次拒绝；已入日志且结果未知的请求保留原有语义。存储事务和现有单条 API 沿用。

测试覆盖一次持久化调用、可只确认已提交前缀、旧任期队列拒绝。13 项通过，类型检查通过。隔离容器中以 16 并发提交 128 条写，Leader 共 10 次本地日志事务，最大批次 16。单次采样约 416 条/秒，P50 24.8 ms、P95 45.2 ms。对原 Leader 先做 3–2 隔离，确认额外 12 条写已追加但未提交，随后 SIGKILL。12 条均为未知结果，多数派仍能提交。重连后 128 条已确认写均可读，本次冲突的 12 条少数派写均未出现在最终状态。 [E1 判定与指标](../../evidence/E1/2026-11-07T10-07-32.331Z--e0847ed4/result.json)
