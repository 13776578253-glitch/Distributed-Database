# 审计收束

## 事务键编码与旧库升级

事务服务接受任意非空 JavaScript 字符串作为键。旧版通过 SQLite TEXT 接收原始键，编码转换会把单独的代理码元替换成 U+FFFD。同一事务中不同键可能因此落入同一个提交分组。WAL 中的 JSON 记录仍保留原始键。

SQLite 以 JSON 字符串编码保存键，按编码分组，加载版本链时解码。旧库升级是启动时独立的 SQLite 事务。它根据原 `appliedLsn` 从完整 WAL 重建版本表，连同 `user_version` 一次提交。恢复阶段随后按原检查点与游标继续处理。迁移中断时 SQLite 回滚，下一次启动可重试。升级会重放旧库已物化的 WAL 前缀，耗时随前缀增长。需要回退到旧版时，使用升级前一同备份的 WAL 和 SQLite 文件。

定向验证覆盖新库、模拟旧版合并的库、历史查询、检查点中的待撤销事务和二次启动。旧库样本从 WAL 恢复了被合并的两个键，重复恢复只产生一条 CLR。

全量 115 项测试和类型检查通过。独立 Compose 重跑 [T01](../../evidence/T01/2026-11-08T14-15-50.333Z--f198395b/result.json) 通过 29 项断言，[T03](../../evidence/T03/2026-11-08T14-17-06.819Z--58518223/result.json) 通过 13 项断言。T03 首次运行在创建对照网络时遇到 Docker 默认地址池耗尽，保留[原始失败记录](../../evidence/T03/2026-11-08T14-16-14.217Z--27c941a6/result.json)。释放本轮已停止的实验容器和网络后复跑，实验卷保留。

另复制上一轮由旧版 HTTP 服务实际写出的 SQLite 和 WAL。升级前 SQLite 只剩一个提交版本，升级后两次打开均分别读回三个键的已提交值 `1`、`2`、`3`，WAL 的 SHA-256 前后一致。

## 控制台数据链路

- 演示请求持有所属会话和尝试序号。停止时先结束调度，已发出的请求保留原会话身份，结算后清理该会话的键。迟到回调和调度属于原会话，当前会话独立统计。
- 写入追踪按所选尝试关联请求和返回。已有的无尝试编号事件按同一操作中相邻的请求与返回配对。回归用例分别选择首次拒绝、重试请求、成功返回和对应的 AppendEntries，确认显示结果与所选证据一致。
- 事务页独立轮询恢复报告。WAL 在重新连通、LSN 变化、恢复报告变化或手动刷新时重新读取，读失败后按轮询间隔重试。离线时保留上次采样并提示。AS OF 前端与代理使用后端的非空键口径，保留键原文。

全量 118 项测试、类型检查和前端构建通过。真实 Edge 连接临时 Observer 和隔离事务容器，分别查询已提交的单空格键和 1,200 字符键。容器停止后页面显示离线，重启后自动显示恢复使用的检查点 7，WAL 从 9 条更新到 12 条，待提交版本归零。演示会话切换和 Leader 重试使用可控时序回归。
