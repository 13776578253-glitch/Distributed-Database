# Raft 协议边界回归与冻结

以 `bb65bd8` 为基线。本轮只补 Raft Core 的确定性测试及冻结记录。测试沿用手动时钟、可控 RPC 投递和内存持久化适配器。任期、有效配置、已应用配置和读屏障仍由 Core 管理。

| 边界 | 调度与判定 | 结果 |
| --- | --- | --- |
| 不同配置视图下的选举 | 通过复制真实配置日志构造旧、联合、最终三种本地视图。最终配置候选者的任期 2 投票应答分别早到、晚到，与任期 3 的联合配置选举交错。记录成功当选者，逐索引对比观察到的已提交前缀。 | 早到时最终配置先提交，联合配置候选者只获得旧侧多数，无法当选。晚到时任期 2 候选者一度当选，但新任期拒绝其追加，索引 4 只提交任期 3 的 no-op。 |
| `configurationIndex` 与旧视图非投票节点 | 联合配置仅复制到一名旧投票成员，原 Leader 退出。两名加入者仍停留在旧视图，接收带配置索引的任期 2 投票请求。 | 两名加入者都持久化投票。联合候选者收齐两侧多数才当选，当前任期 no-op 仍未提交。 |
| 未提交最终配置的截断与重启 | 快照包含已应用的联合配置，后缀只保留未提交最终配置。原 Leader 重启后接收真实新 Leader 的冲突追加，截断后再次重启。 | 有效投票集从后缀里的最终配置回到快照里的联合配置。新最终配置写入后，全体重启恢复相同的有效配置，下一任 Leader 推进已应用边界并保留已确认的 KV。 |
| 联合配置期间的读屏障 | 分别只交付旧侧或新侧的新确认，延迟交付上一个配置已生成的成功 RPC 应答。继续切换到最终配置，再交付延迟的联合配置应答。 | 单侧多数时读保持等待，配置切换使旧屏障返回 `NO_QUORUM`。最终配置的读拿到本轮多数确认后返回索引 3。 |
