# Raft 联合配置与成员变更

以 E3 审查提交 `0275950` 为基线。用户批准 E4。

E4A 在 Core 按最新配置日志计算投票集。联合条目需要旧、新两组各自多数，提交后才追加最终配置；选举、提交和读屏障共用多数判定。截断和快照恢复按持久化前缀与后缀重新计算。先验确定性时序，再进入 E4B。

E4B 使用独立 Compose 项目，增加预配置的非投票节点。HTTP 与命令行控制台提供配置提交和状态查询。真实实验在联合条目已复制但未提交时杀 Leader，随后验加入、移除当前 Leader、从卷恢复配置和确认过的写。

## E4A · Core 验收

31 项测试与类型检查通过。新增时序覆盖只有旧侧或新侧过半时的选举、提交与读屏障；加入者落后时拒绝提议；联合条目复制但未提交时 Leader 崩溃后继续完成变更；冲突截断恢复有效投票集；旧 Leader 被移出后降级，重启从快照恢复非投票状态。

配置在本地日志落盘后生效，旧读屏障随配置切换作废。只有联合条目提交后才能追加最终配置。已应用配置进入快照，有效配置仍可由保留后缀覆盖。 [Raft 论文 §6](https://raft.github.io/raft.pdf#page=11)
