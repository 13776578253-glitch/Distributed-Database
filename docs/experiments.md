# 实验清单

正式实验的命令和结果随实现补充。每次运行将命令、UTC 时间、Git SHA、参数、事件、原始日志和判定写入 `evidence/<ID>/<runId>/`。

## 方向一 · Raft KV

先运行 `pnpm demo`。然后顺序运行 `pnpm experiment R01`、`pnpm experiment R02`、`pnpm experiment R03`。其中 R02 通过应用 RPC 层模拟分区，恢复后比对五个节点的提交索引、日志长度和提交前缀哈希。R03 的调用与返回保存在 `events.jsonl`，供 S4 回放。

| ID | 动作 | 判定 |
| --- | --- | --- |
| R01 | 强制杀死 Leader，再启动该节点 | 在限定时间内重新选举，确认过的写入仍可线性一致地读到 |
| R02 | 双向阻断五节点 RPC，形成 3–2 分区，再恢复 | 多数派提交，少数派无法确认写入，恢复后已提交前缀一致并收敛 |
| R03 | 采集并发读写调用及返回 | 使用同一进程的单调时钟，S4 回放后给出线性一致性判定，另含负例 |
| R04 | 控制复制顺序，先让旧任期条目达到多数副本，再放行当前任期 no-op | 旧任期多数副本阶段提交索引不推进，当前任期条目提交后按序应用前缀。复现命令见[验收报告](current-task/2026-11-06-raft-audit.md) |
| E1 | 独立集群上并发写入，隔离 Leader 后杀掉已追加未确认批次的节点 | 记录事务批数、P50/P95 和吞吐，已确认写全部恢复，未确认写保留未知结果，本次冲突后缀清除 |
| E2 | 分区后多数派先确认新值，再分别请求默认读、stale 读和 safe-follower 读 | 多数派安全读返回新值，少数派 stale 返回旧值，少数派 safe 与旧 Leader 读拒绝，重连后 safe 返回新值 |
| E3B | 在隔离集群暂停一个 Follower，压缩在线节点，写入后缀后恢复 Follower，最后 SIGKILL 并重启 Leader | SQLite 日志行减少，落后节点实际 InstallSnapshot 后继续复制，重启恢复快照和绝对索引后缀，不同边界的已应用 KV 一致 |
| E4B | 六节点隔离环境让旧侧三票复制联合配置，杀 Leader，恢复后用命令行移除现任 Leader | 联合条目在三票下保持未提交，恢复后提交最终配置，保留已确认写；移除节点从快照重启仍是非投票节点 |

## 方向三 · MVCC/WAL

| ID | 动作 | 判定 |
| --- | --- | --- |
| T01 | 在提交前后、检查点和 Redo 中强制终止 | 恢复结果符合持久化 COMMIT 边界，无半提交，AS OF 可由日志核对 |
| T02 | 构造 SI 跨键写偏差，再执行显式加锁版本 | 原始运行打破值班约束，修复运行保持约束 |
| T03 | Undo 写入 CLR 后再次强制终止 | 再次恢复沿撤销链继续，终态与一次完整恢复一致 |
